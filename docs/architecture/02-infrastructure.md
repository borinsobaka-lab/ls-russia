# Инфраструктура и сервисы

Статус: предложено — 2026-10-08. Документ отвечает, из каких сервисов
собрана платформа, какой сервер нужен на старте и как расти. Пошаговая
настройка — `docs/setup/01-timeweb-server.md`; выбор технологий —
`01-tech-stack.md`.

## 1. Исходные требования

- Сотни клубов по России, тысячи клиентов; в первом релизе 300–400
  активных пользователей внутреннего контура (УК и собственники).
- **Все данные — в России** (152-ФЗ): база, файлы, бэкапы, логи ошибок.
  Никаких SaaS с данными за границей.
- Один веб-сервис для сотрудников и отдельное клиентское приложение.
- Выкат по слиянию в `main` без ручных шагов: разработка идёт
  параллельными сессиями Claude Code.
- Минимальная конфигурация на старте, рост по мере нагрузки.

## 2. Схема

```
Интернет ─► Timeweb файрвол (80/443) ─► Traefik (Coolify, TLS) ─┬─► portal (Next.js)      office.<домен>
                                                                 ├─► portal-worker (тот же образ, без домена)
                                                                 ├─► Kong ─► GoTrue / PostgREST / Storage / Studio   api.<домен>
                                                                 ├─► Uptime Kuma            status.<домен>
                                                                 └─► GlitchTip              errors.<домен>
Postgres (контейнер Supabase) ◄── PostgREST, GoTrue, Storage, apply.sh (миграции при старте portal)
Timeweb S3 (СПб) ◄── Storage (файлы), Coolify (бэкапы базы)
Unisender Go ◄── письма; FCM/APNs ◄── push; Telegram ◄── тревоги и уведомления
```

## 3. Сервисы

| Слой | Решение | Почему |
|---|---|---|
| Хостинг | **Timeweb Cloud**, сервер в Москве, Ubuntu 24.04 | в реестре хостеров РКН; трафик серверов не тарифицируется; почасовая оплата; S3, CDN, DNS, файрвол, VPC, балансировщик в одной панели |
| Платформа выката | **Coolify** | деплой по push, TLS сам, логи, веб-терминал, бэкапы баз в S3 |
| База, вход, файлы | **Supabase на своём сервере**: Postgres, GoTrue, PostgREST, Storage, Kong, imgproxy, Studio, meta | managed Supabase в России нет; managed Postgres провайдеров не даёт суперпользователя и расширений, нужных схемам `auth` и `storage` |
| Файлы | **Timeweb S3** как бэкенд Storage + отдельный бакет бэкапов | сервер stateless, диск не растёт, бэкапы в другом городе |
| Почта | **Unisender Go** | российский транзакционный отправитель; зарубежные сервисы за Cloudflare из России работают нестабильно |
| Уведомления | лента в приложении + Web Push + письма + Telegram-бот | push зависит от Google/Apple, поэтому лента — основной канал |
| Ошибки | **GlitchTip** | self-hosted, протокол Sentry |
| Аптайм | **Uptime Kuma** | тревоги в Telegram |
| Метрики и логи | **Grafana + Prometheus + Loki + Alloy** — вторым этапом | на старте достаточно GlitchTip и Kuma |
| CI | **GitHub Actions**, только PR, только затронутое; полный прогон раз в неделю | минуты платные |
| DNS и TLS | DNS Timeweb; Let's Encrypt через Traefik | Cloudflare и зарубежные CDN из России рвутся (ECH); сертификаты НУЦ Минцифры браузеры не принимают |

Чего нет намеренно: Cloudflare, Supabase Realtime, Redis, Kafka,
Elasticsearch, Edge Functions, любые `if (окружение)` в коде — адреса,
ключи и отправители только в переменных окружения.

## 4. Сервер на старте

**Timeweb Cloud, Москва, 4 vCPU / 8 ГБ / 80 ГБ NVMe** (линейка Cloud —
~1 100 ₽/мес, Premium той же конфигурации — ~1 800 ₽/мес) + swap 4 ГБ.

Почему не 2 vCPU / 4 ГБ: стек Supabase занимает 2–2,5 ГБ в покое,
Coolify — около 1 ГБ, а сборка Next.js на шаге «Collecting build traces»
даёт пик в 3–4 ГБ и без swap падает молча по OOM. Тариф у Timeweb
меняется только вверх (диск не уменьшить), поэтому берём с запасом на
год.

| Служба | Память в покое |
|---|---|
| Coolify (панель, Traefik, свои Postgres и Redis) | ~1 ГБ |
| Supabase: `db`, `kong`, `auth`, `rest`, `storage`, `imgproxy`, `meta`, `studio` (без `realtime`, `functions`, `analytics`) | ~2–2,5 ГБ |
| `portal` (1 реплика) | ~200–300 МБ |
| `portal-worker` | ~150 МБ |
| GlitchTip (web, worker, Postgres, Valkey) | ~700 МБ (можно отложить на месяц) |
| Uptime Kuma | ~100 МБ |
| Пик сборки образа | до 3–4 ГБ, уходит в swap |

Итого ~5 ГБ в покое при 8 ГБ. На 300–400 пользователей с SSE-каналами
этого достаточно с запасом.

### Рост

1. **Тесно по памяти или второй продукт в бою** → сервер-наблюдатель
   2 vCPU / 4 ГБ (~1 200 ₽/мес с IPv4): GlitchTip, Kuma, Grafana-стек.
   Подключается к тому же Coolify вторым сервером по приватной сети.
2. **Клиентское приложение (тысячи клиентов)** → база на отдельный
   сервер 8 vCPU / 16 ГБ NVMe; приложения остаются на первом; при пиках
   — временные реплики `portal`/`client` за балансировщиком Timeweb
   (почасовая оплата). База не масштабируется вширь — только вверх.
3. **Сборки мешают работе** → образы собираются в GitHub Actions и
   публикуются в GHCR, Coolify только тянет готовый образ.

## 5. Сеть, домены, TLS

- Домен — в Timeweb (для `.ru` нужна верификация владельца), записи с
  TTL 300. Поддомены: `office` (портал), `api` (Supabase), `coolify`,
  `status`, `errors`, позже `app` (клиенты).
- TLS — Let's Encrypt через Traefik; выпуск требует публичного IPv4 и
  прописанной A-записи до первого выката.
- Файрвол Timeweb: 22 — с IP владельца и из VPC, 80/443 — всем; группа
  файрвола — allow-list **и на исходящий трафик**: TCP/UDP/ICMP наружу
  разрешаются явно.
- Зеркало Docker Hub `https://dockerhub.timeweb.cloud` — Docker Hub за
  Cloudflare и из России тянется с обрывами.
- Telegram Bot API из российских ЦОД открывается только по IPv6 —
  включается IPv6 в сетях Docker.
- DDoS-защита L3–L4 входит в тариф при размещении в VPC Москвы/СПб;
  L7-защита (DDoS-Guard, StormWall, Qrator) — только под реальную атаку.

## 6. Бэкапы и восстановление

- **База**: бэкапы Coolify ежедневно, 30 дней, в бакет `ls-backups`
  (класс Cold, другой город) + еженедельный `pg_dump` с хранением
  полгода. PITR на self-hosted нет: **RPO — сутки**; при более жёстком
  требовании — WAL-архивирование (`pgBackRest`) отдельной задачей.
- **Файлы**: версионирование бакета `ls-files`; отдельный бэкап S3 не
  нужен.
- **Сервер**: образ перед каждым изменением инфраструктуры, «Защита от
  удаления».
- **Проверка восстановления** — раз в квартал: временный Postgres,
  `pg_restore`, пересчёт строк ключевых таблиц (команды — в runbook).
- **Секреты** — менеджер паролей владельца и переменные Coolify; в
  репозитории, чате и документах — никогда.

## 7. Наблюдаемость — порядок внедрения

1. Неделя 1: `/api/health` у портала и воркера (всегда 200, с
   `?strict=1` — 503 при тревоге), Uptime Kuma с тревогами в Telegram,
   пульс воркера push-монитором.
2. Недели 2–4: GlitchTip и SDK в портале с вырезанием персональных
   данных (белый список заголовков, `sendDefaultPii: false`); DSN
   отдаётся браузеру атрибутами `<html>`, а не вшивается в сборку.
3. К клиентскому приложению: сервер-наблюдатель, Grafana + Prometheus +
   Loki, Alloy на ядре (экспортёры node, cadvisor, postgres; логи
   контейнеров); тревоги: диск > 85 %, память > 90 %, CPU > 85 %,
   соединений Postgres > 80, `absent(up)`. Хранение метрик и логов —
   30 дней, событий GlitchTip — 90.

## 8. Стоимость содержания (релизы 1–2: портал для сотрудников)

Цены — открытые прайсы на октябрь 2026, перед оплатой сверять в панели.

| Статья | ₽/мес | Примечание |
|---|---|---|
| Сервер Timeweb Cloud 4 vCPU / 8 ГБ / 80 ГБ NVMe, Москва | 1 100 (линейка Cloud) — 1 800 (Premium) | трафик не тарифицируется; на нём Coolify, Supabase, портал, воркер, Kuma, GlitchTip |
| Публичный IPv4 | 0–150 | если не входит в тариф |
| S3: файлы (Standard) + бэкапы (Cold, ~1 ₽/ГБ) | 100–300 | первые десятки ГБ; растёт с вложениями |
| Домен `.ru` | ~35 (регистрация ~200 ₽, продление 399 ₽/год) | с 10.04.2026 регистрация требует подтверждения через Госуслуги |
| Почта: Unisender Go, пакет 10 000 писем | 1 200 (6 000 писем — 800; первые 2 месяца бесплатно) | ориентир объёма: 300–400 человек, вечерние дайджесты и письма о непрочитанном — 6–10 тыс. писем в месяц |
| Почта, альтернатива: Yandex Cloud Postbox | ~300–500 | 2 000 писем в месяц бесплатно, далее ~$0,66 за 1 000; регион Россия |
| Опции Timeweb: «Отмена удаления», «Аварийная копия», автобэкап сервера | 0–700 | по 200–300 за опцию; бэкапы базы и так уходят в S3 |
| TLS (Let's Encrypt), Web Push (VAPID), Telegram-бот, GitHub Free (2 000 минут CI), GlitchTip и Kuma | 0 | self-hosted и бесплатные тарифы |
| **Итого** | **~2 500–3 500** без опций, **~4 000–4 500** с опциями | ~35–55 тыс. ₽ в год |

Что не входит: время людей на поддержку и разработку (включая подписку
на Claude Code), юридическое сопровождение по 152-ФЗ (уведомление в РКН
бесплатно, консультация — нет), SMS (сотрудникам не нужны: второй фактор
— TOTP), ИИ-помощник редактора (релиз 2, Яндекс, при редком
использовании — сотни рублей).

Стоимость почти не зависит от числа пользователей до ~1 000–2 000
человек: следующая ступень — сервер-наблюдатель (+~650–1 200 ₽) и, к
клиентскому приложению, отдельная база (+3 000–5 000 ₽).

### Переезд на Selectel или другого провайдера

Платформа к провайдеру не привязана: всё в Docker под Coolify, файлы в
S3-совместимом хранилище, адреса в переменных окружения. Переезд — новый
сервер, установка Coolify, восстановление дампа базы, копирование
бакетов (`rclone`), смена переменных и DNS; занимает полдня при объёмах
первых релизов. Сопоставимый сервер Selectel (VDS 4 vCPU / 8 ГБ /
80 ГБ, с IPv4 и 3 ТБ трафика) — ~1 300 ₽/мес; S3 Selectel дороже
(~2,3 ₽/ГБ), облачные серверы Selectel с оплатой по ресурсам — дороже
VDS в 2–3 раза. Selectel так же в реестре хостеров РКН; если у заказчика
там уже есть серверы и договор, размещение у него не меняет ни код, ни
схему выката.
