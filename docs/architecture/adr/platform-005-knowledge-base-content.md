# ADR platform-005: хранение и редактирование статей базы знаний

Статус: предложено — 2026-10-08

## Контекст

База знаний для собственников — первый продукт релиза. У Eventbase
(`apps/docs`) контент лежит markdown-файлами в репозитории и собирается
статикой: правка = PR разработчика. Собственникам и УК нужно: править
самим, черновики, история, доступ по ролям, подтверждение ознакомления,
поиск с морфологией.

## Варианты

1. Markdown в базе + редактор markdown. Таблицы, выноски, вложения,
   видео и ссылки на задачи не выражаются стандартным markdown — получится
   свой диалект без редактора WYSIWYG.
2. HTML в базе + редактор HTML. Хранимый HTML — XSS-поверхность и не
   поддаётся структурным операциям (оглавление, миграции формата).
3. **JSON-документ ProseMirror (TipTap) в базе** (выбрано). Структура
   со схемой; HTML для чтения и текст для поиска строит сервер при
   публикации; схему можно расширять узлами («выноска», «чек-лист»,
   «ссылка на задачу»); тот же редактор годится для описаний задач и
   длинных сообщений. Готов путь к совместному редактированию (Yjs),
   если понадобится.
4. Внешняя CMS/вики (Outline, BookStack, Wiki.js). Отдельный вход,
   отдельные роли, отдельные бэкапы, вторая база; сквозная связка
   «статья → задача всем, кто не прочитал» не получится.

## Решение

- `kb_article_versions.content jsonb` — документ ProseMirror; при
  публикации сервер пишет `content_html` (рендер той же схемой, с
  санитайзером) и `content_text` (для `tsvector`).
- Редактор — TipTap с ограниченным набором узлов, определённым в
  `packages/shared/src/kb-schema.ts` (один источник для редактора,
  рендера и валидации на сервере; неизвестный узел отвергается).
- Картинки и файлы — приватный бакет `kb-files`, загрузка из браузера по
  подписанному URL, в документе — ссылка на `files.id`, адрес
  собирается при показе. Видео — ссылкой на российские хостинги
  (Kinescope, VK Video, RuTube) через узел `embed` с белым списком
  доменов.
- Поиск — `tsvector` конфигурации `russian` по заголовку (вес A), краткому
  описанию (B) и тексту (C) + `pg_trgm` по заголовку для опечаток; запрос
  идёт под RLS — находится только видимое.
- Интерфейс чтения — по образцу `apps/docs` Eventbase: меню с кратким
  описанием под пунктом, текст до 740 px, оглавление справа с подсветкой,
  стрелки «назад/дальше» по порядку раздела, лента экранов, светлая и
  тёмная темы, печать.
- Версии не редактируются и не удаляются; «удалить статью» — архив.

## Последствия

- Зависимости: `@tiptap/*`, `prosemirror-*`, санитайзер (`sanitize-html`
  уже есть в Eventbase). Размер клиентского чанка редактора — ленивый
  `next/dynamic`, читатель его не грузит.
- Экспорт в PDF и импорт из Word/Google Docs — отдельные задачи релиза 2
  поверх того же JSON.
- Описание задачи и длинные сообщения чатов используют урезанную схему
  того же редактора — один набор узлов, одна санитизация.
