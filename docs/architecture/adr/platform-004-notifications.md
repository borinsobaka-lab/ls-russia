# ADR platform-004: уведомления сотрудникам

Статус: предложено — 2026-10-08

## Контекст

Задачи и чаты без уведомлений — Битрикс, в который никто не заходит.
Пользователи — на личных телефонах (iPhone и Android поровну), часть —
за компьютером на ресепшене. Web Push на Android идёт через FCM (Google),
на iPhone работает только из установленной PWA (iOS 16.4+). Из России
доступность FCM и APNs не гарантирована. Почта — есть у всех.
Telegram — есть почти у всех и работает из РФ (Bot API из российских ЦОД
доступен по IPv6).

Eventbase: push двух родов (кампания и событие), воркер, лента
уведомлений в приложении как канал по умолчанию, письма — только для
кода входа; «доставлено» в статистике не существует, только
«отправлено» и «прочитано».

## Варианты

1. Только push. Отклонено: iPhone без установки и любое отключение
   FCM/APNs оставляют человека без уведомлений.
2. Только письма. Отклонено: медленно для чатов, спам-фильтры.
3. **Четыре слоя с одним источником правды** (выбрано): лента в
   портале (`notifications`, всегда) → push → письмо (по правилу
   «не прочитано за 10 минут» для личных и упоминаний; дайджест для
   остального) → Telegram-бот (по желанию пользователя, релиз 2).

## Решение

- **Кому адресовано, решает база**: событие (новое сообщение, назначение
  задачи, упоминание, смена статуса, срок, публикация статьи с
  `requires_ack`) порождает строки `notifications` триггером или RPC,
  с учётом членства и `notification_prefs`; текст собирается при показе
  из `kind` + `vars` (как `system_notices` Eventbase).
- **Доставка — только воркером** через `jobs` (`notify.push`,
  `notify.email`, `notify.telegram`), никогда синхронно в запросе.
  Повторы: временная ошибка — повтор с экспонентой, 404/410 — подписка
  мертва, 400/403 — отказ. Белый список хостов push против SSRF.
- **Письмо через 10 минут**, если уведомление о личном сообщении или
  упоминании не прочитано (`read_at is null`) — одно письмо на чат за
  окно, не на сообщение. Дайджест групп, каналов и задач — вечером в
  19:00 по часовому поясу клуба (`pg_cron` → `jobs`).
- **Тихие часы** и `muted_until` у чатов уважаются всеми каналами, кроме
  ленты.
- **Push без персональных данных в теле**: «Новое сообщение в чате
  „Открытие Казань“» — да; текст сообщения — нет (FCM и APNs за
  границей, 152-ФЗ).
- Прочтение гасит уведомление **действием**, а не заходом в раздел
  (открыл чат — прочитал; открыл задачу — прочитал), и отменяет
  неотправленное письмо (`subject_key`).
- Telegram-бот (релиз 2): привязка по одноразовому коду из портала
  (`telegram_links`), уведомления тем же текстом, что в ленте, кнопка
  «Открыть». Ответить из Telegram нельзя — это уведомление, а не второй
  мессенджер.
- Статистика: «отправлено», «прочитано»; «доставлено» не обещаем.

## Последствия

- Лента в портале — обязательный раздел релиза 1 с ярлыком
  непрочитанного в навигации; её пересчитывает SSE-канал.
- PWA-установка нужна только ради push на iPhone; инструкция установки
  — слой в лейауте, как у Eventbase.
- Нагрузка на почту растёт с числом непрочитанных: Unisender Go, тариф
  по объёму, письма с `track_links: 0`.
