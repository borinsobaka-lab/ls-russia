# Линейка продуктов и порядок релизов

Статус: предложено — 2026-10-08. Названия продуктов снаружи — решение
владельца; в коде — английские идентификаторы (`kb`, `tasks`, `chat`,
`clients`, `crm`), и расхождение имени снаружи и в коде — намеренное:
подписи переименовываются свободно, а папки, таблицы и типы — никогда
без явного запроса (переименование стоит смены адресов и миграции по
живым данным).

## 0. Рамка: один портал, продукты — разделы

Один веб-сервис `apps/portal` (`office.<домен>`), один вход, одна левая
навигация. Продукт — раздел со своими таблицами и своей папкой
`apps/portal/src/app/(portal)/<продукт>/`. Клиентское приложение
(`apps/client`, `app.<домен>`) — отдельный мир: другая аудитория,
другая аутентификация, своя PWA-область (манифест и service worker).

| Релиз | Продукты | Для кого | Готово, когда |
|---|---|---|---|
| **1** | Ядро + База знаний + Задачи + Чаты + PWA портала | УК и собственники, 300–400 человек | 20 собственников-пилотов месяц живут без Битрикса; затем вся сеть |
| **2** | Отчёты по сети, поручения с контролем, Telegram-уведомления, шаблоны, экспорт | те же | закрыты запросы пилота |
| **3** | Клиентское приложение (PWA): расписание, запись, абонементы, оплата, профиль | клиенты студий | пилот в 3–5 клубах |
| **4** | Кабинет клуба: клиенты и абонементы, расписание и загрузка залов, CRM, единое окно переписки с клиентами, права по сотрудникам | собственники и персонал | клубы ведут клиентов здесь |

Релизы 3 и 4 идут параллельно после 2: приложение без кабинета клуба
бессмысленно, кабинет без приложения — CRM без клиентов.

## 1. База знаний (`kb`)

### Что умеет

- **Разделы и дерево статей**: `kb_spaces` («Открытие студии»,
  «Стандарты сервиса», «Маркетинг», «Обучение тренеров»,
  «Юридическое»), внутри — статьи с вложенностью (`parent_id`) и
  порядком редактора.
- **Редактор** — TipTap: заголовки, списки, таблицы, картинки, видео
  (ссылка на российский хостинг или загруженный файл), вложения,
  выноски («важно», «совет»), чек-листы, ссылки на статьи и задачи.
  Содержимое — JSON-документ ProseMirror в `content jsonb`; сервер при
  публикации строит HTML для чтения и чистый текст для поиска
  (ADR `platform-005`).
- **Черновик → публикация → архив**; каждая публикация — строка
  `kb_article_versions` (кто, когда, что изменилось), возврат к любой
  версии.
- **Аудитория**: `audience_roles text[]` (`owner`, `manager`, `trainer`,
  `hq`) и `audience_club_status text[]` (`opening`, `open`); политика
  отбирает строки условием `(cardinality(audience_roles) = 0 or
  audience_roles && (select app.my_role_codes()))`; статья без аудитории
  видна всем вошедшим.
- **«Ознакомлен»**: флаг `requires_ack`; собственник нажимает
  «Ознакомлен» — строка `kb_acks`; УК видит отчёт «кто из клубов прочитал
  новый стандарт» и ставит задачу остальным одной кнопкой.
- **Чтение**: `kb_reads` — отметку ставит браузер после показа (не
  prefetch).
- **Поиск**: `tsvector` с конфигурацией `russian` по заголовку (вес A),
  описанию (B) и тексту (C) + `pg_trgm` по заголовку для опечаток; идёт
  под RLS — находится только видимое.
- **Вопрос к статье** открывает чат с автором или разделом поддержки УК
  — обсуждение живёт в чатах, а не в комментариях под статьёй.
- **Файлы** — приватный бакет `kb-files`, загрузка из браузера по
  подписанному URL, выдача подписанными ссылками по сессии; картинки
  пережимаются сервером, SVG отклоняется.
- Релиз 2: шаблоны статей, экспорт в PDF, ИИ-помощник редактора через
  Яндекс.

### Интерфейс чтения

Три колонки: меню раздела с кратким описанием под пунктом, текст
шириной до 740 px, справа оглавление с подсветкой текущего раздела;
стрелки «назад/дальше» по порядку раздела; на телефоне — выезжающее
меню; светлая и тёмная темы; версия для печати; якоря латиницей.

### Таблицы

| Таблица | Колонки | Политики |
|---|---|---|
| `kb_spaces` | `id`, `org_id`, `title`, `slug`, `icon`, `sort_order`, `audience_roles[]`, `is_published` | select по аудитории; write — `has_permission(org,'kb.editor')` |
| `kb_articles` | `id`, `org_id`, `space_id`, `parent_id`, `slug`, `title`, `summary`, `status`, `current_version_id`, `requires_ack`, `audience_roles[]`, `audience_club_status[]`, `sort_order`, `published_at`, `search tsvector generated`, `created_by`, `updated_at` | select: published по аудитории, черновики — редакторам; write — `kb.editor` |
| `kb_article_versions` | `id`, `article_id`, `version_no`, `content jsonb`, `content_html`, `content_text`, `change_note`, `created_by`, `created_at` | select как статья; insert — редактор; update/delete — нет |
| `kb_attachments` | `id`, `article_id`, `file_id → files`, `title`, `sort_order` | как статья |
| `kb_reads`, `kb_acks` | `(article_id, user_id)`, метки времени, `version_id` | своя строка; отчёты УК — RPC `kb_ack_report(article)` |

## 2. Задачи (`tasks`)

Главный сценарий — не личный список дел, а **поручение сети**: УК
ставит одну задачу на сотни клубов и видит, кто сделал.

### Что умеет

- **Доски** (`task_boards`) у сети (отделы УК) и у клуба (создаётся
  вместе с клубом). Колонки — статусы из справочника доски
  (`task_statuses`: код, название, цвет, `is_done`), по умолчанию
  «Новая / В работе / На проверке / Готово / Отменена».
- **Задача**: название, описание (тот же редактор, урезанный),
  исполнитель, постановщик, наблюдатели, срок, приоритет, клуб,
  подзадачи, чек-лист, вложения, метки, ссылка на статью базы знаний.
- **Поручение сети** (`task_assignments`): шаблон + выбор клубов (все /
  по статусу / по региону / список) → по задаче на клуб исполнителю по
  роли, сводка «сделано N из M», напоминание отстающим одной кнопкой.
- **Повторяющиеся задачи** (`task_recurrences`) — экземпляры создаёт
  воркер по `pg_cron`.
- **Комментарии** с упоминаниями `@имя`; **история** (`task_events`) —
  только добавление.
- **Представления**: доска, список, «Мои задачи» (поручено мне /
  поставлено мной / наблюдаю), календарь сроков; фильтры по клубу,
  исполнителю, метке, просрочке. Списки — курсором, без точного
  «сколько всего».
- **Уведомления**: назначили, упомянули, сменили статус, срок через
  сутки, просрочено.

### Видимость

| Кто | Видит |
|---|---|
| org admin / staff | все доски сети и клубов |
| owner / manager клуба | доска своего клуба, задачи сети, где клуб — исполнитель, свои |
| administrator / trainer | задачи, где он исполнитель/постановщик/наблюдатель; доска клуба — по настройке клуба |

`app.task_visible(task_id)` — одна security-definer-функция на все
политики задач и комментариев.

### Таблицы

`task_boards`, `task_statuses`, `tasks`, `task_watchers`,
`task_checklist_items`, `task_comments`, `task_attachments (file_id)`,
`task_labels`, `task_label_links`, `task_events`, `task_assignments`,
`task_recurrences`. У всех `org_id`, у клубных — `club_id`; счётчики
комментариев и подзадач держат триггеры.

## 3. Чаты (`chat`)

### Что умеет

- **Виды** (`chats.type`): `dm` (личный, `dm_key` из двух id), `group`
  (явный состав), `channel` (объявления: пишут админы, читают все;
  ответы тредом или выключены), `club` (служебный чат клуба с УК —
  создаётся вместе с клубом), `task` (обсуждение задачи).
- **Членство явное у всех видов** — список участников, роли в чате
  (`admin`/`member`), выход, исключение.
- **Сообщения**: текст до 4 000 знаков с лёгкой разметкой, вложения
  (файлы до 20 МБ, картинки до 5 МБ), ответ, пересылка, реакции,
  **редактирование и удаление своих** с историей (`chat_message_history`
  — корпоративный след не пропадает), закрепление, упоминания.
- **Прочитанность**: `chat_members.last_read_message_id`; в личном —
  «прочитано», в группе — «прочитали N». Непрочитанное считает RPC
  `chat_list_mine()` с потолком «99+».
- **Поиск** по сообщениям видимых чатов (`tsvector russian`).
- **Живое обновление** — SSE-канал, одно соединение на вкладку,
  комната-снимок раз в секунду (ADR `platform-003`); хвост открытой
  переписки дописывается без перерисовки. «Печатает…» — релиз 2.
- **Уведомления**: личные и упоминания — сразу (push; письмо через
  10 минут, если не прочитано); группы и каналы — по настройке
  (`muted`, дайджест).
- **Модерация**: админ сети удаляет сообщение и исключает участника
  через RPC с записью в `audit_log`, не читая переписку целиком.

### Таблицы

| Таблица | Ключевые колонки |
|---|---|
| `chats` | `id`, `org_id`, `type`, `title`, `avatar_path`, `club_id`, `task_id`, `dm_key unique`, `created_by`, `last_message_id`, `last_message_at`, `settings jsonb` |
| `chat_members` | PK `(chat_id, user_id)`, `role`, `joined_at`, `left_at`, `last_read_message_id`, `muted_until`, `notify_mode` — update от участника только трёх последних через `app.only_columns` |
| `chat_messages` | `id bigint identity`, `chat_id`, `sender_id`, `body`, `body_format`, `reply_to_id`, `forwarded_from_id`, `attachments jsonb`, `client_key` (идемпотентность: unique `(chat_id, sender_id, client_key)`), `edited_at`, `deleted_at`, `pinned_at`, `created_at`; индекс `(chat_id, id desc)` |
| `chat_message_history` | `message_id`, `body_before`, `changed_at` — только добавление |
| `chat_reactions` | PK `(message_id, user_id, emoji)` |
| `chat_mentions` | `(message_id, user_id)` — заполняет триггер; источник уведомлений |

Политика select сообщений — `app.chat_member(chat_id)`: участник с
`left_at is null`.

## 4. PWA портала и уведомления (релиз 1)

- Манифест и service worker — маршрутами приложения, а не плагином;
  правила — `06-engineering-rules.md` § 5.
- Установка на телефон — слой с инструкцией для iPhone и Android; на
  iPhone push работает только из установленного приложения.
- Уведомления — четыре слоя (лента в портале всегда; push; письмо;
  Telegram-бот с релиза 2) — ADR `platform-004`.

## 5. Клиентское приложение (`apps/client`, релиз 3) — что закладывается сейчас

- **Клиент принадлежит сети**: `clients (id, org_id, phone unique, email,
  first_name, last_name, birth_date, avatar_path, status, created_at)`;
  связь с клубами — `client_club_links`; абонементы — `memberships
  (client_id, club_id | null для сетевых, plan_id, …)`.
- **Вход по телефону**: код по SMS или через бота Telegram/MAX; сессия
  90 дней со скользящим продлением; `client_sessions`,
  `client_login_codes`; лимиты по паре «телефон + IP».
- **Клеймы** `cl_client_id`, `cl_org_id`; политики клиентов — отдельная
  матрица в тесте.
- **Согласия по 152-ФЗ** — `client_consents (client_id, kind, version,
  given_at, ip, source)`; текст политики — статья базы знаний с версией.
- **Платежи** — ЮKassa / CloudPayments / Т-Банк, чеки 54-ФЗ через кассу
  шлюза; интерфейс поставщика один, реализации — модули.
- **Сборки в магазины** — оболочкой (Capacitor/TWA) над той же PWA.

## 6. Кабинет клуба (релиз 4) — что закладывается сейчас

- Разделы в том же `apps/portal`, под клубом: `/clubs/<id>/clients`,
  `/schedule`, `/crm`, `/inbox`.
- **Единое окно переписки с клиентами**: `im_channels (club_id, kind:
  telegram|max|vk|phone; секреты — в таблице без политик)`,
  `im_conversations (client_id, channel_id, assigned_to)`, `im_messages`.
  WhatsApp в России заблокирован с февраля 2026 — не планируется;
  Telegram Bot API и MAX Bot API (нужна верификация юрлица) — первые
  каналы, VK — третий.
- **Воронка лидов** (`crm_leads`, `crm_stages`, `crm_activities`) с
  импортом из amoCRM.
- **Расписание** (`schedule_slots`, `schedule_bookings`, `rooms`;
  тренеры — `club_members` с ролью `trainer`), запись и лист ожидания с
  замками в базе (`pg_advisory_xact_lock` на слот: «3 места — 20
  одновременных запросов» решается в базе, не в коде).

Эти таблицы не создаются в релизе 1, но принадлежность клиента сети и
имена сущностей зафиксированы, чтобы задачи, чаты и уведомления не
пришлось переделывать.

## 7. Матрица видимости релиза 1

| Данные | super_admin | org admin | org staff | club owner/manager | club administrator/trainer |
|---|---|---|---|---|---|
| Клубы, люди, роли | ✓ | ✓ | читает | свой клуб (правит owner/manager) | свой клуб, читает |
| База знаний | ✓ | пишет | читает; пишет с `kb.editor` | по аудитории | по аудитории |
| Доски сети | ✓ | ✓ | ✓ | задачи, где клуб исполнитель | нет |
| Доска клуба | ✓ | ✓ | ✓ | ✓ | по настройке клуба / свои |
| Чаты | только свои + модерация | свои + модерация | свои | свои | свои |
| Журнал действий | ✓ | по своей сети | нет | нет | нет |
| Аналитика сети | ✓ | ✓ | по правам | по своему клубу | нет |

Личные чаты и личные уведомления не читает никто, кроме участников, —
включая супер-админа; это закрыто политиками, а не договорённостью.
