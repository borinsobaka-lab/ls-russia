# Инженерные правила

Статус: 2026-10-08. Правила, по которым пишется код платформы. Каждое —
с технической причиной, чтобы сессия понимала, что именно сломается,
если правило нарушить. Корневой `CLAUDE.md` ссылается сюда; правила
конкретного приложения живут в его `CLAUDE.md` и `docs/patterns/`.

## 1. База данных

1. **Четыре политики по операциям, никогда `for all`.** DELETE
   проверяется только по `using`; `using(читать) with check(писать)`
   разрешает удалять читателю.
2. **Личность в политиках — `app.staff_id()`**, не `auth.uid()`: она
   пуста без второго фактора и у заблокированной учётки.
3. **Функции записи не возвращают null** — `coalesce(…, false)`: иначе
   `if not can_manage` в PL/pgSQL молча пропускает.
4. **Условие с подзапросом к невидимой таблице — в security-definer-
   функцию**; stable-функции в политике — в скобках `(select app.f())`.
5. **Update от рядового пользователя стережёт `app.only_columns(...)`**;
   `with check` сверяет сеть/клуб цели ссылки.
6. **Клеймы читаются только через `auth.jwt()`** (внутри `nullif(…, '')`);
   роль сессии — `current_setting('role', true)`.
7. **Свои клеймы на каждый мир доступа** (`sub`/`aal`, `cl_*`); клейм
   одного мира никогда не называется как в другом.
8. **RLS фильтрует строки, не колонки**: секрет в широко читаемой
   строке — колоночный `revoke` или отдельная таблица без политик.
9. **Служебные таблицы** — RLS включён, политик нет, только
   `service_role`.
10. **Хвост сортировки — `id`**; списки — курсором «время + id»; точное
    «сколько всего» не считается; PostgREST режет ответ до 1 000 строк
    без признака — читать страницами.
11. **Счётчики держат триггеры** (колонка, а не `count(*)` на показе);
    гонки на одном объекте — `pg_advisory_xact_lock`; идемпотентность —
    уникальный ключ от клиента; журналы — только добавление.
12. **Миграции только добавляются**; идемпотентный DDL (`if not
    exists`, `drop policy if exists` + `create`); новое значение enum —
    отдельным файлом; `drop function if exists` при смене сигнатуры;
    порядок триггеров — именами `aa_*`/`zz_*`; `updated_at` — триггером.
13. **Новая таблица** = `org_id` (+ `club_id`), каскадные внешние ключи,
    индексы на FK, четыре политики, строка в матрице теста, бакет и
    запись в реестр файлов, если есть файлы.
14. **Схема меняется только миграциями**; Studio — для просмотра
    (правки в Studio делают объекты чужими владельцу `postgres`, и
    выкат падает на «must be owner»).

## 2. Сервер приложения

1. **Запись, которая обязана получиться, — через `mustWrite`**: PostgREST
   не бросает исключений, ошибка приходит полем `error`; `await` без
   разбора — молча потерянная запись. Отказ называет класс
   (`forbidden`/`duplicate`/`check`/`schema`/`fail`), `details` наружу не
   выносится.
2. **Проверка прав в начале каждого серверного действия** (`requireStaff`,
   `requireClub`), обёрнутая в React `cache()` — одна проверка на рендер;
   запись идёт ключом пользователя, RLS — второй рубеж.
3. **Вход разбирается `zod`**; `required` в разметке ничего не
   гарантирует; тела маршрутов читаются потоком с пределом.
4. **Действие, остающееся на странице, заканчивается `revalidatePath`**,
   не `redirect` (редирект на тот же путь — пустой экран); `redirect` —
   только при смене адреса или для `?error=`/`?ok=`.
5. **Одно серверное действие на вкладку одновременно** — второе поверх
   идущего замораживает роутер; кнопка, после которой ждут, крутит
   спиннер всегда.
6. **Строки форм читаются `select("*")`**, списки — поимённо; миграция
   едет тем же PR, что и код, пишущий в новую колонку (`PGRST204`
   роняет всю форму вместе с набранным текстом).
7. **Никаких циклов «на каждый элемент — свой await»** — `mapLimit`
   с пределом; раздел собирается двумя волнами запросов, не больше.
8. **Общие значения — в модуле без директив**: константа из модуля с
   `"use client"` на сервере превращается в ссылку-объект.
9. **Сорвавшийся запрос ≠ пустые данные**: функции возвращают `null`,
   а не `[]`, и ошибку не кешируют как «нет такого».
10. **Фон — только воркером через `jobs`**; цикл со `sleep`, не
    `setInterval`; пульс воркера — отдельный таймер; клиент Supabase для
    таймеров и комнат — без `cache()` (кешированный пережил бы токен).
11. **Адрес ссылок в письмах — из `PORTAL_PUBLIC_URL`**; `Host` и
    `X-Forwarded-Host` недоверенные; в standalone-сборке Next
    перезапускает middleware на переписанном запросе с `Host:
    localhost`, поэтому внешний хост читается через свой заголовок.
12. **Редирект из обработчика — относительный `Location`** (за прокси
    `req.url` — адрес контейнера).
13. **Почта**: `track_links: 0`, `track_read: 0` (антивирусы сжигают
    одноразовые ссылки); «200 + success» не значит «ушло» — проверять
    `failed_emails`; данные пользователя в письме экранируются; у
    письма есть текстовая часть.
14. **Один образ на все окружения, без `NEXT_PUBLIC_*`**: всё, что нужно
    браузеру (DSN ошибок, адрес хранилища), сервер отдаёт атрибутами
    `<html>` или ответом.

## 3. Клиент (браузер)

1. **Серверные компоненты грузят данные, клиентские — только
   интерактив**; функция в клиентский компонент не передаётся — только
   серверное действие.
2. **Дизайн-токены в `@theme`**, никаких захардкоженных цветов; статусы —
   двумя токенами (цвет-индикатор и цвет-текст с посчитанным
   контрастом); иконки — из одного модуля; эмодзи в интерфейсе нет.
3. **Формы не теряют набранное**: ошибка возвращает на ту же вкладку с
   сохранёнными значениями; обязательное поле помечено; фокус в окне
   ставится без прокрутки.
4. **Длинные ленты прокручиваются своей областью**, переписка читается с
   конца и листается курсором назад; при листании истории отметка
   прочтения не пишется.
5. **Прочтение гасит действие, а не заход в раздел**; отметку ставит
   браузер после показа; `prefetch` разделов с отметками запрещён.
6. **Любая картинка из хранилища просит копию под свой размер**
   (преобразования Storage), заглушка аватарки рисуется разметкой под
   картинкой всегда.
7. **Пустых состояний три** (нет данных / нет доступа / ошибка загрузки),
   и они различимы.
8. **Устаревшая сборка во вкладке** перезагружается сама (событие
   `hello{build}` канала и обработка `ChunkLoadError`) — когда вкладка
   видна и человек не печатает.

## 4. Живые обновления (ADR `platform-003`)

- Одно SSE-соединение на вкладку; `retry` с разбросом; событие
  `fallback` кодом 200 (ответ не-200 закрывает `EventSource` навсегда);
  пинг раз в 15 с; `X-Accel-Buffering: no`.
- Комната-снимок в процессе, тик 1 с, флаг `busy`; личные переписки —
  через функцию «id, время, состав — без содержимого».
- Клиент по умолчанию — `router.refresh()`; переписка — хвост
  `?after=<lastId>` без перерисовки; ярлыки непрочитанного — склейка
  1 с, один запрос в полёте, только на видимой вкладке.
- Пределы соединений на пользователя и на процесс; ведро в памяти
  делится на `APP_REPLICAS`.

## 5. PWA и push

- Манифест и service worker — маршрутами; `start_url` и `scope` без
  слеша на конце (проверка scope в Chrome — сравнение префикса строки,
  а Next отвечает 308 на слеш); `id` манифеста не меняется никогда.
- SW: `skipWaiting` + `clients.claim`, кеши версионированы; кешируется
  только `/_next/static`; **навигация не кешируется** (чужой профиль на
  общем телефоне); офлайн-страница кладётся попыткой (`cache.add(...).catch`),
  а не `addAll` — отклонённая установка SW гасит push.
- В теле SW нет регулярок с экранированием (`/\/$/` в шаблонной строке
  превращается в `//`) — `scripts/check-service-worker.mjs` вычисляет
  шаблон как JS и парсит результат.
- `Notification.requestPermission()` — только из обработчика тапа;
  смена VAPID-ключа требует `unsubscribe`; у каждого обещания — лимит
  времени; временная ошибка push — повтор, 404/410 — подписка мертва.
- Белый список хостов push (FCM, APNs, Mozilla, WNS) против SSRF;
  таймаут отправки обязателен.
- Установка на телефон — слой с инструкцией; `beforeinstallprompt` не
  используется; «уже установлено» определяет синхронный скрипт в
  `<head>` до первого кадра.

## 6. Сборка, образ, выкат

- Dockerfile: multi-stage `node:22-alpine`; слои — манифесты →
  `pnpm install --frozen-lockfile` → исходники → `pnpm --filter <app>
  build`; `output: "standalone"`, `outputFileTracingRoot` — корень
  монорепо; `USER node`; `HEALTHCHECK` через `node -e "fetch(...)"`
  (в alpine нет curl, а проверка Coolify идёт внутри контейнера).
- `MIGRATE_ON_START=1` у веб-контейнера: `apply.sh` перед `node
  server.js`; воркер миграции не накатывает.
- Watch Paths у каждого приложения Coolify — иначе любой коммит
  пересобирает всё.
- Номер версии приложения повышается каждым коммитом в `main` и виден
  в подвале — иначе «не доехало» не отличить от «не сработало».
- `/api/health` всегда 200 с тревогами в теле, `?strict=1` — 503;
  `/api/version` — коммит и время старта.
- Шрифты — файлами; сборка не ходит в интернет.

## 7. Тексты и имена

- Интерфейс по-русски, строки прямо в разметке; **словарь терминов** в
  `CLAUDE.md` приложения («задача», «чаты», «клуб», «собственник»,
  «сотрудник УК»); англицизмы («таск», «мессенджер», «чекин») не
  используются.
- Имя снаружи и имя в коде — разные вещи: подписи правятся свободно,
  идентификаторы — никогда без запроса.
- Комментарии в коде и миграциях — прозой, с «почему»; у миграции —
  шапка «зачем / что было / что стало».
