# Платформа Lady Stretch — правила работы в этом репозитории

Платформа диджитал-продуктов сети студий растяжки: портал сотрудников и
собственников (база знаний, задачи, чаты; позже кабинет клуба) и
клиентское приложение. Язык интерфейсов, комментариев, документации
**и переписки с владельцем — русский**, включая заголовки и подписи.

Статус (08.10.2026): **написан план, кода ещё нет.** Начинать с
`docs/architecture/00-master-plan.md`, затем `docs/setup/02-repo-bootstrap.md`.

## Структура (целевая)

```
apps/portal/        # портал (Next.js 15, App Router, Tailwind 4); он же воркер при PORTAL_ROLE=worker
apps/client/        # клиентское приложение (релиз 3)
packages/shared/    # ОБЩИЕ КОНТРАКТЫ: типы, зеркалящие схему; коды прав; схема редактора
supabase/migrations # ОБЩИЙ КОНТРАКТ: схема Postgres + RLS (только добавление)
supabase/tests/     # исполняемые тесты изоляции; run.sh поднимает одноразовый Postgres
scripts/            # проверки CI и операционные скрипты
docs/architecture/  # план, стек, модель данных, продукты, безопасность, инженерные правила, ADR
docs/setup/         # runbook'и
docs/patterns/      # правила по темам, на которые ссылается CLAUDE.md приложения
```

Прочти перед работой: `docs/architecture/03-data-model.md` (роли, RLS,
миры доступа), `04-products.md` (что строим), `06-engineering-rules.md`
(как пишем). Решения с вариантами — `docs/architecture/adr/`.

## Правила параллельной работы

0. **`main` — ствол, ветки короткие.** Начинай раунд с `git fetch origin`
   и `git log --oneline origin/main -20`. Коммиты — прозой, с «почему».
1. **Одна задача = одна папка приложения.** Чужие `apps/*` не трогай.
2. **Общие слои меняются отдельно.** `packages/shared` и
   `supabase/migrations` — отдельным небольшим PR до зависящих задач.
   Нужен тип или таблица, а задача не про контракты — остановись и скажи.
3. **Миграции — только добавление.** `supabase/migrations/<YYYYMMDDHHMMSS>_<имя>.sql`;
   применённые файлы не редактируются. Новое значение enum — отдельным
   файлом.
4. **Не переименовывай и не перемещай** общие файлы без запроса.
5. **Решение шире своей папки — в файл** (`CLAUDE.md` или ADR) тем же
   коммитом. Сказанное в чате для других сессий не существует.
6. **Изоляцию проверяет тест**: `bash supabase/tests/run.sh`. Меняешь
   политику — обновляй матрицу в `01-core-rls.sql` тем же коммитом.
7. **Минуты CI платные**: новая проверка — шаг в «Быстрых проверках»;
   CI только на PR и только по затронутому; полный прогон раз в неделю.
8. **Бюджет правил**: корневой `CLAUDE.md` ≤ 40 КБ, приложения ≤ 60 КБ;
   тема длиннее абзаца — в `docs/patterns/`, здесь строка со ссылкой.

## Архитектурные инварианты (не нарушать)

- **Один Postgres, мультитенантность через RLS.** `orgs → clubs`,
  членства `org_members` и `club_members`. Новая таблица получает
  `org_id` (+ `club_id`), каскадные FK, индексы и четыре политики в той
  же миграции.
- **Политика по операциям, не `for all`**: у DELETE нет `with check`.
- **Личность сотрудника — `app.staff_id()`**, не `auth.uid()`: пуста без
  второго фактора (`aal2`) и у заблокированной учётки. Функции записи не
  возвращают `null`.
- **Update рядового пользователя стережёт `app.only_columns(...)`**;
  `with check` сверяет сеть/клуб цели ссылки.
- **Свои клеймы у каждого мира** (`sub`/`aal`, `cl_*`); клеймы читаются
  только через `auth.jwt()`.
- **`service_role` — только в модулях из списка ADR platform-001**;
  `scripts/check-service-role.mjs` проверяет.
- **Подзапрос к невидимой таблице — в security-definer-функцию**;
  stable-функции в политике — `(select app.f())`.
- **Сортировка до однозначного порядка** (хвост — `id`); списки курсором;
  точное «сколько всего» не считается.
- **Все бакеты приватные**; загрузка из браузера по подписанному URL,
  путь выбирает сервер; удаляя строку с файлом, удаляй файл.
- **Запись через `mustWrite`**; отказ называет класс причины. Действие,
  остающееся на странице, заканчивается `revalidatePath`.
- **Фон — только воркером через `jobs`**; расписание — `pg_cron`.
- **Живые обновления — SSE + опрос** (ADR platform-003). WebSocket,
  Realtime, Redis — не вводить без нового ADR.
- **Уведомления: адресата решает база, доставляет воркер, лента в
  портале — источник правды**; push без персональных данных в теле.
- **Второй фактор — TOTP через GoTrue, обязателен** (ADR platform-002);
  маршруты из писем сессию не выдают; ссылки — из `PORTAL_PUBLIC_URL`.
- **Лимиты — в базе** (`auth_rate_events`); троттл, не блокировка;
  `CLIENT_IP_HEADER` — доверенный заголовок.
- **Заголовки безопасности ставит middleware из окружения**;
  `NEXT_PUBLIC_*` не используется — образ один на любое окружение.
- **Никаких адресов, ключей, доменов в коде.** Новая переменная —
  запись в Coolify той же задачей.
- **Шрифты в репозитории**, `next/font/google` не используется.
- **Имя снаружи и имя в коде — разные вещи.** Англицизмы в интерфейсе не
  используются: «задача», «чаты», «клуб», «собственник».
- **ИИ — через поставщика Яндекс** (`lib/ai/`).

## Миграции и выкат

**Миграции применяются сами при выкате.** Push в `main` → Coolify
собирает образ → контейнер `portal` с `MIGRATE_ON_START=1` запускает
`supabase/apply.sh` (журнал `app.schema_migrations`, суммы, advisory
lock) → стартует → healthcheck → замена старого. Упавшая миграция
оставляет старый контейнер; чинится **новой** миграцией.

Ручное применение вредно: без строки в журнале следующий выкат падает на
«relation already exists». Исключение — **разрушающие миграции**
(`drop table/column`, `truncate`): их применяет человек в тихое время с
бэкапом и отмечает в журнале.

**Миграция едет тем же PR, что и код, который на неё опирается**:
пишущая сторона рассинхрон не переживает (`PGRST204` роняет форму).

## Команды

```bash
pnpm install
pnpm --filter portal dev        # порт 3000, apps/portal/.env.local
pnpm --filter portal build      # прод-сборка с проверкой типов — перед PR
bash supabase/tests/run.sh      # одноразовый Postgres, все миграции, матрица RLS
```

## Деплой и готовность

Push в `main` → Coolify выкатывает затронутое. **Готовую задачу заливай
сам, не спрашивая** (решение владельца). Готова = сборка затронутого
проходит, CI на PR зелёный. Сомнение по сути задачи — до работы. В
описании PR — имя файла миграции и что меняется в схеме.
